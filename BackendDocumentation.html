📖 01. Introduction

Emind is a full-featured e-commerce management system developed using Laravel 12. It is designed to manage products, role-permissions, orders, users, payments, setup configurations, and reports through a secure admin dashboard and RESTful APIs for web and mobile applications.

⚡ Modern Stack

Built with Laravel 12, PHP 8.2+, and MySQL for optimal performance and developer experience.

🔐 Secure

JWT authentication, role-based access control, and secure payment gateway integration.

📊 Complete Management

Full admin dashboard for products, orders, customers, shipping, and system configuration.

🤖 AI Support

Integrated Gemini AI for intelligent chat support and customer assistance.

🚀 05. Environment Configuration Guide

Overview: This guide will walk you through the complete installation process step by step. Follow each step carefully to ensure a successful installation of the Emind E-Commerce Management System.

Prerequisites: Make sure you have PHP 8.2+, MySQL 8.0+, Composer installed, and access to your server's database management panel (phpMyAdmin, cPanel, etc.).

Pre-Installation Steps (Before Running the Installer):

Follow these steps in order before accessing the installation wizard through your browser.

Step 1: Extract/Unzip the Project

Description: First, you need to extract the downloaded project file from CodeCanyon.

What to do:

  • Download the project zip file from CodeCanyon
  • Extract/unzip the project file to your desired location
  • For Local Development: Extract to your local development folder (e.g., C:\xampp\htdocs\emind or /var/www/html/emind)
  • For Production/Server: Extract to your server's public_html directory (or web root directory)
  • Make sure all files and folders are extracted properly

Step 2: Create Database

Description: Create a new MySQL database for the project.

What to do:

  • Access your database management panel (phpMyAdmin, cPanel, MySQL command line, or any database tool)
  • Create a new database (e.g., "emind_db", "emind_database", or any name you prefer)
  • Note down the following information (you will need these later):
    • Database Name
    • Database Username
    • Database Password
    • Database Host (usually "localhost" or "127.0.0.1")
  • Make sure the database user has full privileges (SELECT, INSERT, UPDATE, DELETE, CREATE, DROP, ALTER, etc.)

Step 0: Installation Welcome Screen

Step 3: Open Project in IDE/Terminal

Description: Open the project in your preferred code editor or terminal to proceed with setup.

What to do:

  • For VS Code:
    • Open Visual Studio Code
    • Go to File → Open Folder (or press Ctrl+K, Ctrl+O)
    • Select your extracted project folder
  • For Other IDEs: Open your IDE (PhpStorm, Sublime Text, etc.) and import/open the project folder
  • For Terminal/Command Prompt:
    • Open Terminal (Mac/Linux) or Command Prompt/PowerShell (Windows)
    • Navigate to the project directory using: cd path/to/your/project
    • Example: cd C:\xampp\htdocs\emind (Windows) or cd /var/www/html/emind (Linux/Mac)
  • Make sure you are in the root directory of the project (where you can see files like: composer.json, .env.example, artisan, etc.)

Step 4: Create .env File

Description: Create the environment configuration file from the example file using terminal command.

What to do:

  • Make sure you are in the project root directory (where .env.example file exists)
  • Open your terminal/command prompt in the project root directory
  • Run the following command to copy the example environment file:
  • 
cp .env.example .env
  • For Windows Command Prompt: Use copy .env.example .env
  • For Windows Git Bash/PowerShell: Use cp .env.example .env
  • For Linux/Mac: Use cp .env.example .env
  • This will create a new .env file in your project root directory
  • Now run below command to set app key in your .env file
    • 
php artisan key:generate
  • Now run below command to set jwt secret in your .env file. Important Note: Please make sure that the Apache server and MySQL are running if you setup for local developement.
    • 
php artisan jwt:secret
  • Now save the .env file after running these commands

APP_FAKER_LOCALE Locale for fake data generation during testing/seeding. No
DB_CONNECTION Database driver. Options: mysql, pgsql, sqlite. Yes
DB_HOST Database host address. Usually 127.0.0.1 or localhost. Yes
DB_PORT Database port. MySQL default is 3306. Yes
DB_DATABASE Database name you created in Step 2. Replace with your actual database name. Yes
DB_USERNAME Database username. Replace with your database username. Yes
DB_PASSWORD Database password. Leave empty if no password, otherwise enter your database password. Yes
SESSION_DRIVER Session storage driver. Options: file, database, redis. No
SESSION_LIFETIME Session lifetime in minutes. Default is 120 minutes (2 hours). No
SESSION_ENCRYPT Enable session encryption. Set to true for enhanced security. No
CACHE_STORE Cache driver. Options: database, file, redis. No
QUEUE_CONNECTION Queue connection driver. Options: database, redis, sync. No
MAIL_MAILER Mail driver. Use log for testing, smtp for production. No
MAIL_HOST SMTP server host (e.g., smtp.gmail.com for Gmail). No
MAIL_PORT SMTP port. Common: 587 (TLS), 465 (SSL), 2525. No
MAIL_USERNAME SMTP username (your email address). No
MAIL_PASSWORD SMTP password (your email password or app password). No
MAIL_FROM_ADDRESS Default "from" email address for outgoing emails. No
MAIL_FROM_NAME Default "from" name (uses APP_NAME by default). No
STRIPE_KEY Stripe Publishable Key. Get from Stripe Dashboard. No
STRIPE_SECRET Stripe Secret Key. Get from Stripe Dashboard. Keep this secret! No

CHAT_API_KEY Chat API key for customer support chat functionality. No
GEMINI_API_URL Gemini AI API URL for AI-powered chat support. Get from Google AI Studio. No
JWT_SECRET JWT secret key for API authentication. Generate using: php artisan jwt:secret. No

REACT_REDIRECT_URL Frontend React application URL for redirects (if using React frontend). No

PHP_CLI_SERVER_WORKERS Number of workers for PHP built-in server (development only). No

Configure domain:

Make sure you have an Apache web server installed. For configuring domain in your VPS server, you must configure a vhost (Virtual Host) configuration file. Follow the steps below to configure vhost config file for both domain.

  • Step 1: Navigate to Apache Sites Directory
  • cd /etc/apache2/sites-available/
  • Step 2: Create a Virtual Host Configuration File
  • sudo nano /etc/apache2/sites-available/your_domain.com.conf
  • Add the following content:
  • <VirtualHost *:80>
    ServerAdmin
    webmaster@your_domain.com
    ServerAlias
    www.your_domain.com
    ServerName
    your_domain.com
    DocumentRoot
    /var/www/your_domain.com/public_html
    <Directory /var/www/your_domain.com/public_html>
    Options
    -Indexes +FollowSymLinks
    AllowOverride
    All
    Require
    all granted
    </Directory>
    ErrorLog
    ${APACHE_LOG_DIR}/error.log
    CustomLog
    ${APACHE_LOG_DIR}/access.log combined
    </VirtualHost>
  • Save the file and exit the text editor.
  • Step 3: Enable the virtual host configuration file
  • sudo a2ensite your_domain.com.conf
  • Step 4: Reload the Apache2 server
  • sudo systemctl reload apache2
  • Step 5: Test the Virtual Host. Open your web browser and navigate to http://your_domain.com. You should see your website.

    • Domain propagation:

    Domain propagation refers to the process of updating DNS (Domain Name System) records across the internet, allowing a newly purchased domain to become accessible globally.

    To initiate the process, configure an A record for your domain.

    Info:

    Setup SSL with Certbot on Apache:

    SSL (Secure Socket Layer) is crucial for securing data transmitted between the user’s browser and your web server. Certbot is a free, open-source software tool for automatically managing SSL certificates.

    In this guide, we’ll walk through the process of setting up SSL for your Apache web server using Certbot.

    Before you begin, make sure you have:

    • An Apache web server installed.
    • A registered domain pointing to your server’s IP address.
    • The domain is accessible over HTTP (port 80).

    SSH into the server

    • Step 1: SSH into the server. Access the server hosting your HTTP website via SSH using a user account with sudo privileges.
    • Step 2: Install snapd. Ensure that you install snapd and carefully follow any provided instructions to activate classic snap support.
    • Refer to the instructions provided on snapcraft’s website for installing snapd.
    •  install snapd
    • Step 3: Remove certbot-auto and any Certbot OS packages
    • If you have any Certbot packages installed via an OS package manager such as apt, it’s advisable to uninstall them before installing the Certbot snap. This ensures that when you execute the command “certbot,” the snap version is utilized rather than the one from your OS package manager. For removing the certbot from the system run the following command
    • sudo apt-get remove certbot
    • Step 4: Install Certbot. Execute this command on the command line of your machine to install Certbot.
    • sudo snap install --classic certbot
    • Step 5: Prepare the Certbot command. Run the following instruction on the command line of your machine to ensure that the certbot command can be executed.
    • sudo ln -s /snap/bin/certbot /usr/bin/certbot
    • Step 6: Choose how you’d like to run Certbot. Run this command to get a certificate and have Certbot edit your apache configuration automatically to serve it, turning on HTTPS access in a single step.
    • sudo certbot --apache
    • Or, just get a certificate
    • If you’re feeling more conservative and would like to make the changes to your apache configuration by hand, run this command.
    • sudo certbot certonly --apache
    • Step 7: Test automatic renewal
    • The Certbot packages on your system come with a cron job or systemd timer that will renew your certificates automatically before they expire. You will not need to run Certbot again, unless you change your configuration. You can test automatic renewal for your certificates by running this command:
    •  sudo certbot renew --dry-run
    • Step 8: Confirm that Certbot worked
    • To confirm that your site is set up properly, visit https://yourwebsite.com/ in your browser and look for the lock icon in the URL bar.

    MySQL Database and User Setup:

    Setting up a MySQL database involves creating a database, creating a user, and assigning that user appropriate privileges. This guide will walk you through the process using MySQL commands.

    Before you begin, make sure you have:

    • MySQL installed on your server.
    • MySQL root access or a user with sufficient privileges.

    Follow the below steps:

    • Step 1: Log in to MySQL
    • sudo mysql
    • Step 2: Create a Database
    • CREATE DATABASE your_database_name;

      • Replace your_database_name with the desired name for your database.

    • Step 3: Create a MySQL User
    •  CREATE USER 'your_username'@'localhost' IDENTIFIED BY 'your_password';

      • Replace your_username with the desired username and your_password with the desired password for the user.

    • Step 4: Grant All Privileges to the User for the Database
    • GRANT ALL PRIVILEGES ON your_database_name.* TO 'your_username'@'localhost';
    • Step 4: Flush the privileges 
    • FLUSH PRIVILEGES;

      • Replace your_database_name with the name of the database created in Step 2 and your_username with the username created in Step 3

    • Step 5: Exit MySQL 
    •  EXIT;
